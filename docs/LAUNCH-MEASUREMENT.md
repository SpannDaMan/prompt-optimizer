# Launch Measurement

GitHub stars are a visibility signal, not the product outcome. Prompt Optimizer should be measured as an adoption and qualified-demand funnel.

## Funnel

1. Discovery: repository views and referral sources.
2. Evaluation: README engagement, clones, install attempts, demo runs, and documentation visits where observable.
3. Adoption: reproducible issues, feature requests, discussions, forks, and repeat contributors.
4. Commercial intent: team-rollout questions, private customization requests, and support inquiries.
5. Sustainability: GitHub Sponsors activity and any later separately approved paid offering.

## Initial scorecard

| Metric | Source | Why it matters |
|---|---|---|
| Unique visitors and views | GitHub traffic | Separates reach from repeat browsing. |
| Top referrers | GitHub traffic | Shows which launch channels produce qualified visits. |
| Clones | GitHub traffic | Stronger evaluation signal than a page view. |
| Stars and forks | GitHub repository | Social proof and adaptation intent. |
| Reproducible issues | GitHub Issues | Product defects and real use cases. |
| Team inquiries | Support or Discussions | Qualified commercial demand. |
| Sponsors | GitHub Sponsors | Direct community support. |

## Privacy boundary

Version 0.1.x contains no plugin telemetry. Do not add background tracking or transmit prompts to measure usage. Prefer GitHub's aggregate repository metrics and voluntary user feedback. Any future opt-in telemetry requires a separate design, privacy review, and release decision.

## Review cadence

- Day 1: confirm links, install instructions, and visible repository metadata.
- Day 7: review referral sources, clones, issues, and confusion patterns.
- Day 30: decide whether to continue, revise positioning, prepare Agent Smith Router, or stop.

Do not use stars alone as the launch verdict.
